# راه‌اندازی و استقرار

راهنمای جامع پیکربندی، استقرار و نگه‌داری ربات فایل‌استور در بستر رسمی سرورلس تلگرام.

---

## فلسفه معماری بدون متغیر محیطی (Zero-Env)

این ربات بر اساس معماری نوین **عدم وابستگی به متغیرهای محیطی (Zero-Env)** طراحی شده است:
- **عدم استفاده از `process.env`:** ایزوله‌های سرورلس تلگرام به فایل‌های محلی `.env` یا متغیرهای هاستینگ وابسته نیستند.
- **پیکربندی پویای پایگاه داده:** کلیه تنظیمات زمان اجرا (سقف دانلود، شناسه کانال ذخیره‌سازی، کانال لاگ، وضعیت تعمیرات) درون جدول `system_config` ذخیره شده و از طریق دستورات یا پنل شیشه‌ای تنظیمات مدیریت می‌شوند.
- **شناسایی هویت زنده:** نام کاربری و هویت ربات به صورت پویا با متد بومی `api.getMe()` دریافت می‌گردد.
- **راه‌اندازی اولیه بدون تنظیمات قبلی:** ثبت مالک در اولین استقرار از طریق دستور امن `/setbotowner` (یا `/ermia`) انجام می‌شود و نیازی به قرار دادن دستی شناسه عددی در کد یا تنظیمات نیست.

## روش‌های استقرار

### روش اول: پایپ‌لاین خودکار GitHub Actions (پیشنهادی)

استقرار به‌طور کامل و خودکار از طریق `.github/workflows/deploy.yml` با هر پوش به شاخه `main` انجام می‌گیرد:

1. مخزن را روی گیت‌هاب فورک کرده یا پروژه را پوش کنید.
2. در تنظیمات مخزن گیت‌هاب به مسیر **Settings > Secrets and variables > Actions** بروید.
3. تنها راز مورد نیاز را ثبت کنید:
   - `TGCLOUD_TOKEN`: توکن دسترسی ابزار `@tgcloud/cli` که از بخش سرورلس تلگرام دریافت کرده‌اید.
4. تغییرات را به شاخه `main` بفرستید. پایپ‌لاین CI عملیات زیر را به ترتیب اجرا می‌کند:
   ```bash
   tgcloud fetch
   tgcloud push
   tgcloud migrate --safe
   tgcloud webhook sync
   ```
5. فرایند استقرار مستقیماً توسط نسخه محلی خط فرمان (`./node_modules/.bin/tgcloud`) و بدون وابستگی به اسکریپت‌های توسعه محلی اجرا می‌شود.

::: tip فورک‌های بدون نیاز به تنظیمات (Zero-Config)
فورک‌های پروژه کاملاً بدون تنظیم اضافه عمل می‌کنند: تنها متغیر لازم راز `TGCLOUD_TOKEN` است. همچنین درخواست‌های Pull Request به دلایل امنیتی هیچ دسترسی به رازها ندارند.
:::

---

### روش دوم: استقرار مستقیم با خط فرمان `@tgcloud/cli`

جهت دیپلوی دستی از روی سیستم محلی و مهاجرت ایمن جداول:

1. وارد پوشه مخزن شوید:
   ```bash
   cd telegram-filestore-tgcloud
   ```

2. وابستگی‌های اجرایی و ابزار خط فرمان را نصب کنید:
   ```bash
   npm install
   ```

3. ماژول‌ها را ارسال و پایگاه داده و وب‌هوک را همگام کنید:
   ```bash
   npx @tgcloud/cli push
   npx @tgcloud/cli migrate --safe
   npx @tgcloud/cli webhook sync
   ```

---

### روش سوم: بارگذاری دستی در ویرایشگر وب BotFather

برای اپراتورهایی که مستقیماً از ویرایشگر تحت وب سرورلس BotFather استفاده می‌کنند:

1. فایل‌های آماده درون پوشه `dist/` را به این صورت جای‌گذاری کنید:
   - فایل `dist/schema.js`: در تب Database Schema.
   - فایل `dist/single-file-core.js`: نسخه یکپارچه شامل تمام منطق‌های تجاری (`helpers`, `buttons`, `delivery`, `bundles`, `admin`) به همراه دیکشنری دوزبانه ادغام‌شده.
   - فایل `dist/handlers/message.js`: در تب Message Handler.
   - فایل `dist/handlers/callback_query.js`: در تب Callback Query Handler.
2. تغییرات را در پنل ذخیره و منتشر نمایید.

## اقدامات پس از استقرار و راه‌اندازی اولیه

### ۱. تعیین مالک اصلی ربات (`/setbotowner`)

بلافاصله پس از اولین استقرار روی پایگاه داده خالی:
1. گفتگوی خصوصی (PV) با ربات خود را در تلگرام باز کنید.
2. دستور راه‌اندازی اولیه را ارسال نمایید:
   ```
   /setbotowner
   ```
   *(نام مستعار: `/ermia`)*
3. در صورت خالی بودن جدول، شناسه عددی تلگرام شما به عنوان مالک اصلی (سطح ۴) ثبت شده و امکان ثبت مجدد برای همیشه قفل می‌شود.

---

### ۲. تنظیم کانال ذخیره‌سازی فایل‌ها (`/setstoragechannel`)

اتصال کانال ذخیره‌سازی، امکان ارسال دسته‌جمعی و پرسرعت فایل‌ها با `copyMessages` را فراهم می‌کند:
1. یک **کانال خصوصی** در تلگرام ایجاد کنید.
2. ربات را به عنوان **مدیر (Administrator)** با دسترسی‌های زیر اضافه کنید:
   - ارسال پیام (Post Messages)
   - ویرایش پیام (Edit Messages)
   - حذف پیام (Delete Messages)
3. شناسه عددی کانال (مانند `-1001234567890`) را به دست آورید.
4. در چت با ربات، دستور زیر را ارسال کنید:
   ```
   /setstoragechannel -1001234567890
   ```
5. برای غیرفعال‌سازی کانال آرشیو:
   ```
   /setstoragechannel off
   ```

---

### ۳. تنظیم کانال ثبت وقایع (`/setlogchannel`)

لاگ‌های حسابرسی، خطاهای امنیتی و تغییرات ادمین‌ها می‌تواند به یک کانال مشخص ارسال شود:
1. کانال خصوصی جدیدی بسازید و ربات را در آن مدیر کنید.
2. کانال را متصل نمایید:
   ```
   /setlogchannel -1009876543210
   ```
3. همچنین می‌توانید لاگ‌ها را در پی‌وی خود دریافت کنید (`/setlogchannel owner`) یا آن را غیرفعال کنید (`/setlogchannel off`).

---

### ۴. کانال‌های عضویت اجباری (`/channels`)

تعریف حداکثر **۸** کانال برای عضویت اجباری کاربران:
1. دستور `/channels` را اجرا کنید.
2. طبق مراحل پنل شیشه‌ای تعاملی، کانال‌های عمومی یا خصوصی را اضافه کنید.
3. **بررسی کاملاً غیرفعال (Passive):** ارزیابی عضویت صرفاً از طریق متد غیرفعال `getChatMember` انجام می‌شود و هیچ‌گونه درخواست جهش یا ساخت لینک دعوت به API ارسال نمی‌گردد؛ این امر ریسک خطای محدودیت ۴۲۹ را کاملاً از بین می‌برد. درخواست‌های بررسی عضویت به صورت هم‌زمان در دسته‌های حداکثر ۶تایی ارسال می‌شوند.
